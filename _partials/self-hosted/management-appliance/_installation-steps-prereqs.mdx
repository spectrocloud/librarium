- ISO management software installed on your local machine, such as [`mkisofs`](https://linux.die.net/man/8/mkisofs) or [`genisoimage`](https://linux.die.net/man/1/genisoimage).

- Access to the [Artifact Studio](https://artifact-studio.spectrocloud.com/) to download the slim Appliance ISO and the accompanying content bundle.

  :::tip

  If you do not have access to Artifact Studio, contact your Spectro Cloud representative or [open a support ticket](https://support.spectrocloud.io/).

  :::

- We recommend the following resources for each node. You can install {props.version} on one or three nodes. For
  production environments, provision three nodes in advance. Refer to the <PaletteVertexUrlMapper edition={props.edition} text="Size Guidelines" palettePath="/install-palette#size-guidelines" vertexPath="/install-palette-vertex#size-guidelines"/> for additional sizing information.

  - 8 CPUs per node.

  - 16 GB memory per node.

  - Two disks per node.

    - The disk used for installation must be 300 GB minimum and 500 GB is recommended. This disk is used for the Appliance ISO stack.

      <details>

      <summary> Prepare the installation disk </summary>

      You specify the device in the TUI as guided during the **Install {props.version}** steps.

      :::warning

      On legacy BIOS systems, the firmware attempts to boot devices in the order listed in the BIOS screen. To boot from the installed OS, the selected disk must be either the first device in the BIOS boot order or the only bootable device.

      :::

      If there are any partitions on the device you plan to use for the installation, you must delete them. For example, if the device is `/dev/sda`, issue the following command to delete all partitions on the device.

      ```bash
      wipefs --all /dev/sda
      ```

      :::danger

      Deleting partitions will erase all data on the device. Ensure that you back up any important data before proceeding.

      :::

      </details>

    - The second disk, which is used for the storage pool, must be at least 500 GB. The default device selected is `/dev/sdb`. You can change the default device during the cluster creation steps in Local UI.

      :::danger

      This disk is wiped as part of the installation process. If using an existing disk, ensure that you back up any important data before proceeding.

      :::

  - At least one removable media connection must be available to attach the Appliance ISO. This can be a physical or virtual connection depending on your infrastructure provider.

- TCP/5080 must be accessible on each Edge host so that you can access Local UI during the installation. This is the
  default Local UI port. For additional network ports required to operate {props.version}, refer to
  <VersionedLink text="Self-Hosted Network Communications and Ports" url="/architecture/networking-ports#self-hosted-network-communications-and-ports"/>.

- SSH access to the Edge hosts if you plan to upload the content bundle with the Palette CLI or enroll the Secure Boot
  key with MokManager.

- Relevant permissions to install {props.version} on the Edge hosts including permission to attach or mount the Appliance ISO and set Edge hosts to
  boot from it.

  :::warning

  The Appliance ISO is only supported on Unified Extensible Firmware Interface (UEFI) systems. Ensure you configure the Edge hosts to boot from the ISO in UEFI mode.

  :::

- If you are using Proxmox Virtual Environment (VE) as the infrastructure provider for Palette, set the VM CPU type to `host`. The default setting in the Proxmox UI is typically different, and leaving it unchanged can result in MongoDB compatibility issues. For more information on CPU types, refer to the [Proxmox VE documentation](https://pve.proxmox.com/pve-docs/chapter-qm.html#_cpu_type). 

- If using an external registry instead of the internal Zot registry that is provided, you will need to provide the following information during the Palette installation process.

  <details>

  <summary> External registry requirements </summary>

  - The DNS/IP endpoint and port for the external registry.
    - Ensure the nodes used to host the Palette management cluster have network access to the external registry server.
  - The username for the registry.
  - The password for the registry.
  - (Optional) The Certificate Authority (CA) certificate that was used to sign the external registry certificate in Base64 format.

    You can get the Base64 encoded entry from your certificate by using the following command. Replace `<certificate-file>` with the filename of your certificate file.

    ```bash
    base64 --wrap 0 <certificate-file>
    ```

  </details>

- If you have an [Ubuntu Pro](https://ubuntu.com/pro) subscription, you can provide the Ubuntu Pro token during the
  Palette installation process. This is optional but recommended for security and compliance purposes.

- A virtual IP address (VIP) must be available for the {props.version} management cluster. You specify the VIP when you create the cluster. The VIP is used for load balancing and high availability and must be
  accessible to all nodes in the {props.version} management cluster.

  <details>

  <summary> How to discover free IPs in your environment </summary>

  You can discover free IPs in your environment by using a tool like `arping` or `nmap`. For example, you can issue the
  following command to probe a CIDR block for free IP addresses.

  ```bash
  nmap --unprivileged -sT -Pn 10.10.200.0/24
  ```

  This command will scan the CIDR block and output any hosts it finds.

  ```shell hideClipboard title="Example nmap output"
  Nmap scan report for test-worker-pool-cluster2-6655ab7a-tyuio.company.dev (10.10.200.2)
  Host is up.
  All 1000 scanned ports on test-worker-pool-cluster2-6655ab7a-tyuio.company.dev (10.10.200.2) are in ignored states.
  Not shown: 1000 filtered tcp ports (no-response)
  ```

  For any free IP addresses, you can use `arping` to double-check if the IP is available.

  ```bash title="Example arping command"
  arping -D -c 4 10.10.200.101
  ```

  ```shell hideClipboard title="Example arping output"
  ARPING 10.10.200.101 from 0.0.0.0 ens103
  Sent 4 probes (4 broadcast(s))
  Received 0 response(s)
  ```

  If you receive no responses like the example output above, the IP address is likely free.

  </details>
