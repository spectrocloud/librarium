{props.version} automatically propagates the image pull secret to clusters. You can track the status of this
propagation to determine whether every cluster received the secret. The system console shows which tenants have
clusters that did not receive the secret. You can then drill down into each tenant to find which clusters do not have
the secret.

### Prerequisites

- {props.version} 4.10.0 or later.
- The system console requires system administrator access to a self-hosted deployment.
- The Tenant Settings view requires tenant administrator access to the tenant you want to inspect.

### Monitor Propagation from the System Console

System administrators of a self-hosted deployment can use the system console when they want to determine which tenants
are missing the image pull secret on one or more clusters.

1. Log in to the {props.version}
    <PaletteVertexUrlMapper
        edition={props.edition}
        text="system console"
        url="/system-management/#access-the-system-console/"
    />.

2. From the left main menu, select **Administration**.

3. Select the **Hardened Images** tab.

4. Scroll to the propagation status panel below the **Pull secret** field. The panel reports one of the following
   states:

   - **Propagation In Progress**: {props.version} is still distributing the pull secret. Wait for the state to update.
   - **Propagation Complete**: every tenant received the pull secret on every cluster. No action is required.
   - **Propagation Failed**: one or more tenants have clusters that did not receive the pull secret.

5. When propagation has failed, review the tenant table below the banner. Each row shows the tenant and a **Clusters**
   ratio of clusters that received the secret over the tenant's total clusters. Use the following controls to work with
   the table:

   - **Filter by tenant name**: enter a tenant name to narrow the list.
   - **Refresh**: fetch the latest propagation status.
   - **Export as CSV**: download the tenant list for offline review.
   - **Ignore this tenant**: select the ignore action on a row to ignore the tenant when calculating propagation
     failures.

6. To investigate why the clusters within a tenant did not receive the pull secret, follow the steps in
   [Monitor Propagation from Tenant Settings](#monitor-propagation-from-tenant-settings) using an account with tenant
   administrator access to that tenant.

### Monitor Propagation from Tenant Settings

Tenant Settings names the clusters in your tenant that did not receive the pull secret and shows the reason each one
failed, so you can act on the specific clusters.

1. Log in to the {props.version} as a tenant administrator.

2. Select **Tenant Settings**.

3. Under **Security**, select **Hardened Images**.

4. Review the table. Each row shows the affected cluster, its project, and the failure reason. Common
   failure reasons include connectivity loss to the management plane, the
   [Pause Agent Upgrades](/clusters/cluster-management/platform-settings/pause-platform-upgrades/) feature excluding the
   cluster from Palette agent upgrades or a Palette version
   older than 4.10.0 running on the cluster. For guidance on interpreting each reason and restoring propagation, refer
   to the
   [Image Pull Secret Not Propagated to Workload Clusters](/troubleshooting/system-management/#pull-secret-not-propagated)
   scenario.

5. Use the following controls to work with the table:

   - **Search**: enter a cluster name to narrow the list.
   - **Project**: filter the list to clusters in a specific project.
   - **Failure Reason**: filter the list to clusters that failed for a specific reason.
   - **Refresh**: fetch the latest propagation status.
   - **Export as CSV**: download the cluster list for offline review.
   - **Ignore this cluster**: select the ignore action on a row to exclude the cluster when calculating
     propagation failures.
