**(4.7.x to 4.8.x)** {props.edition} 4.8 upgrades MongoDB to 8.0, which does not start if the stored MongoDB Feature
Compatibility Version (FCV) is still `6.0`. Clusters whose MongoDB data was first created on {props.edition} 4.5.x
through 4.6.9 might still be at FCV 6.0 and must be raised to 7.0 before upgrading to {props.edition} 4.8. Your current
{props.edition} version does not indicate whether this applies; check the value directly. If you proceed with FCV at
`6.0`, the `mongo` Pods in the `hubble-system` namespace enter `CrashLoopBackOff` with
`Invalid feature compatibility version value '6.0'`.

To read the current FCV, set the `KUBECONFIG` environment variable to point to the management cluster kubeconfig file,
then run the command for your platform.

<Tabs queryString="platform" defaultValue={props.edition === "Palette VerteX" ? "vertex" : "palette"}>

<TabItem label="Palette" value="palette">

```shell
kubectl exec --namespace hubble-system mongo-0 --container mongo -- bash -c \
  'mongosh \
     --username "$MONGO_INITDB_ROOT_USERNAME" \
     --password "$MONGO_INITDB_ROOT_PASSWORD" \
     admin --quiet \
     --eval "printjson(db.adminCommand({ getParameter: 1, featureCompatibilityVersion: 1 }))"'
```

</TabItem>

<TabItem label="Palette VerteX" value="vertex">

```shell
kubectl exec --namespace hubble-system mongo-0 --container mongo -- bash -c \
  'mongosh \
     --username "$MONGODB_INITDB_ROOT_USERNAME" \
     --password "$MONGODB_INITDB_ROOT_PASSWORD" \
     --host "$HOSTNAME" \
     --tls \
     --tlsCAFile /var/mongodb/tls/ca.crt \
     --tlsCertificateKeyFile /var/mongodb/tls/tls-combined.pem \
     --tlsAllowInvalidHostnames \
     admin --quiet \
     --eval "printjson(db.adminCommand({ getParameter: 1, featureCompatibilityVersion: 1 }))"'
```

</TabItem>

</Tabs>

If the returned value is `7.0` or later, no action is required. If the value is `6.0`, raise it on the ReplicaSet
primary. To find the primary, use the `MONGO_PRIMARY` snippet in
<VersionedLink text="Self-Hosted Palette or Palette VerteX Upgrade Hangs" url="/troubleshooting/palette-upgrade/#self-hosted-palette-or-palette-vertex-upgrade-hangs" />.
From a `mongosh` session on the primary, run the following commands and confirm that all three ReplicaSet members
return `7.0`.

```javascript
db.adminCommand({ setFeatureCompatibilityVersion: "7.0", confirm: true })
db.adminCommand({ getParameter: 1, featureCompatibilityVersion: 1 })
```

The `confirm: true` argument is required on MongoDB 7.0 and later. Raising FCV cannot be undone in place. If the
upgrade has already failed with the error above, refer to
<VersionedLink text="Scenario - MongoDB Feature Compatibility Version Mismatch after Palette Upgrade" url="/troubleshooting/enterprise-install/#scenario---mongodb-feature-compatibility-version-mismatch-after-palette-upgrade" />.
