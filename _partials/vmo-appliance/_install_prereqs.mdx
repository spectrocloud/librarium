- Launchpad for VMs Appliance supports enrolling the DRBD signing key with MokManager. It also supports Secure Boot for
  Dell servers with UEFI and Hewlett Packard Enterprise iLO 5.
  Use the following sections to configure and install Secure Boot for Launchpad for VMs Appliance.

  <details>

  <summary>Enroll the DRBD Signing Key with MokManager</summary>

  This guide describes how to enroll the DRBD signing key into the MOK list using `mokutil` and MokManager.

  Use this method when:

  - The BIOS `db` enrollment method does not load the DRBD module successfully.
  - You need to enroll the key from inside the OS without entering BIOS.

  ## Prerequisites

  - SSH access to the appliance node with `sudo` privileges.
  - The `MOK.der` certificate file available on the node. For example, `/tmp/MOK.der`.
  - A console or remote console session to interact with the blue MokManager screen after reboot.

  ## Enroll DRBD Signing Key with MokManager

  1. Place `mmx64.efi` on the EFI partition. The Launchpad for VMs Appliance ships `mmx64.efi` in the
     OS file system but does not always copy it to the EFI System Partition (ESP). Without this file on the ESP,
     MokManager cannot launch at reboot.

     Run the following commands on the node.

     ```bash
     MP=/tmp/cos_grub_fix
     mkdir -p "$MP"
     mount /dev/sda1 "$MP"
     install -m 0755 /usr/lib/shim/mmx64.efi "$MP/EFI/boot/mmx64.efi"
     ls -la "$MP/EFI/boot/"
     sha256sum /usr/lib/shim/mmx64.efi "$MP/EFI/boot/mmx64.efi"
     umount "$MP"
     rmdir "$MP"
     ```

     Verify both `sha256sum` outputs match. This confirms the copy is intact.

     :::info

     `/dev/sda1` is the typical EFI partition. If your node uses a different disk, use `lsblk -f` to identify the
     FAT32 EFI partition.

     :::

  2. Import the DRBD signing key with the following `mokutil` command.

     ```bash
     sudo mokutil --import /tmp/MOK.der
     ```

  3. When prompted, set a temporary password. You enter it again at the blue screen in step 4. Any password works
     because it is only used once.

     Confirm the import is queued.

     ```bash
     sudo mokutil --list-new
     ```

     The DRBD signing key appears in the output.

  4. Reboot the node.

     ```bash
     sudo reboot
     ```

  5. When the system reboots, a blue **MokManager** screen appears. Complete the enrollment.

     1. Select **Enroll MOK**.
     2. Select **View key 0** and confirm it is the DRBD signing key.
     3. Select **Continue**.
     4. Select **Yes** to confirm enrollment.
     5. Enter the temporary password you set in step 2.
     6. Select **Reboot**.

     The system continues booting normally.

  6. After boot, confirm the key is enrolled in the MOK list and visible to the kernel.

     ```bash
     # Confirm the key is in the MOK list
     sudo mokutil --list-enrolled | grep -i "DRBD Module Signing"

     # Confirm the kernel has the key in its keyring
     sudo keyctl list %:.machine 2>/dev/null | grep -i drbd
     sudo keyctl list %:.platform 2>/dev/null | grep -i drbd
     ```

     The DRBD signing key appears in at least one of these outputs.

  ### Troubleshooting

  If `mokutil --import` returns `SKIP: already in db`, the DRBD key is already enrolled in firmware `db`, which causes
  `mokutil` to skip the import. Remove the key from `db` first, using BIOS or `racadm bioscert delete`, and then retry
  step 2.

  If no blue MokManager screen appears at reboot, confirm `mmx64.efi` is present at `\EFI\boot\mmx64.efi` on the ESP.
  Repeat step 1 if it is missing.

  <summary>Install Secure Boot on Hewlett Packard Enterprise iLO 5</summary>

  Before you begin, ensure that you have iLO 5 access with privileges to launch the remote console and change BIOS settings.
  You also need the `MOK.der` certificate file on your local computer.
  Skip to step 4 if you have already downloaded the certificate file.

  1. Navigate to [Artifact Studio](https://artifact-studio.spectrocloud.com/).
  2. Select the version corresponding to your {props.edition} installer. Then, select **Show Artifacts**. The artifact
     list appears.
  3. **Download** the **MOK Key for Secure Boot** file.
  4. Power on or reboot the server. When prompted during Power-On Self-Test (POST), press **F9** to enter
     **System Utilities**.
  5. Select **System Configuration** and press **ENTER**.
  6. Select **BIOS/Platform Configuration (RBSU)** > **Server Security** > **Secure Boot Settings** >
     **Advanced Secure Boot Options**.
  7. Select **DB - Allowed Signatures Database** > **Enroll Signature**. If Secure Boot is currently enabled, the
     **Enroll Signature** option is unavailable. Temporarily disable Secure Boot and repeat the process.
  8. Drag the `MOK.der` file from your desktop onto the iLO Remote Console window. iLO mounts it as a virtual USB
     device automatically.
  9. Confirm any prompts.
  10. Verify that the new entry appears under **DB - Allowed Signatures Database** > **View Signatures**. You can also
      verify the DB keys with the following commands.

      ```shell
      mokutil --db
      sudo keyctl list %:.platform
      ```

  11. Press **ESC** to exit the menus until the **Save and Exit** option is available.
  12. Save your changes. Exit the menu and reboot the server.

  <summary>Install Secure Boot on Dell Servers with UEFI</summary>

  Before you begin, you need the `MOK.der` certificate file on your local computer.
  Skip to step 4 if you have already downloaded the certificate file.

  1. Navigate to [Artifact Studio](https://artifact-studio.spectrocloud.com/).
  2. Select the version corresponding to your {props.edition} installer. Then, select **Show Artifacts**. The artifact
     list appears.
  3. **Download** the **MOK Key for Secure Boot** file.
  4. Power on the server. Issue the following command to create a virtual CD/DVD drive containing an ISO file with the
     `MOK.der` certificate. Alternatively, you can save the file to a FAT32-formatted USB drive.

     ```shell
     mkisofs -output key.iso -volid cidata -joliet -rock MOK.der
     ```

  5. Reboot the server. When the Dell logo appears, press **F2**. The **System Setup** menu opens.
  6. Select **System BIOS** > **Boot Settings**.
  7. Ensure that the **Boot Mode** is set to **UEFI**.
  8. Press **ESC** to return to **Boot Settings**.
  9. Select **System Security** > **Secure Boot Settings**.
  10. Toggle **Secure Boot** to **Enabled** and **Secure Boot Policy** to **Custom**.
  11. Select **Secure Boot Custom Policy Settings** > **Authorized Signature Database (db)**.
  12. Select **Import New Entry**. Then, select the virtual CD/DVD drive or USB drive containing the `MOK.der` file.
  13. Save your changes. Press **ESC** to return to **Authorized Signature Database (db)**.
  14. Select **View Entries**. The `MOK.der` file shows in the database as **DRBD Module Signing**. You can also
      verify the DB keys with the following commands.

      ```shell
      mokutil --db
      sudo keyctl list %:.platform
      ```

  15. Save your changes. Exit the menu and reboot the server.

  </details>

- If you have an [Ubuntu Pro](https://ubuntu.com/pro) subscription, you can provide the Ubuntu Pro token during the
  Launchpad for VMs installation process. This is optional but recommended for security and compliance purposes.

- Configure the network with a bridge network set to `br0`. For more information about network considerations, review
  [VMO Network Configuration Considerations](/vm-management/vmo-appliance/vmo-networking/).

- A virtual IP address (VIP) must be available for the Launchpad for VMs management cluster. The Launchpad for VMs
  installation process assigns the VIP and uses it for load balancing and high availability. The VIP must be accessible
  to all nodes in the Launchpad for VMs management cluster.
